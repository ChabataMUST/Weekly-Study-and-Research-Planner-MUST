# Weeks 1 and 2: design and feasibility

Our first two milestones test whether timetable input and weekly PDF output can support the same study workflow. The working prototype uses dated class occurrences and weekly records as the connection between them. The week numbers refer to the project plan.

## Week 1: settle the workflow and data contract

We selected CSV as the initial import route because our current school timetable can be viewed or captured as an image. A student prepares the rows, and the importer then checks the structure and values. Each occurrence needs a stable key so that correcting a room or time does not create a duplicate or break a note link.

The weekly page brings together classes, assignment instructions, examination scope and research notes. A research record can stand alone when there is no relevant class. Report preparation uses the records already visible for that week, with a title, summary and a choice of which records to include.

The [design notes](design.md) document the screen flow and initial schema. The [input specification](import-format.md) defines required fields, validation rules and reimport behaviour. Sample inputs provide normal, changed and invalid cases for the next milestone.

## Week 2: implement and check the two paths

The import path validates the whole file before presenting a preview. Confirmation saves the batch in one transaction. Cancellation leaves the timetable unchanged, and a stale preview cannot overwrite a more recent import. Existing occurrences are updated in place so that linked notes keep their identities.

The reporting path accepts selected records and an optional timetable, renders Chinese and English text and saves both the selected values and the resulting PDF. Each export has its own stored version. Later changes to timetable data therefore do not alter an earlier report.

The local application, example PDF and automated tests are included in this release. The 20 tests cover validation, data persistence, import transactions, weekly selection and PDF versioning. The customer group has confirmed the requirements questionnaire; acceptance testing of the completed application remains a later project activity.
